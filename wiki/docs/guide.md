# 使用说明

这个 Wiki 的写法固定成几条规矩，目的只有一个：**知识只写一次，而且能被验证**。

## 三条约定

### 结论先行

每篇开头一句话讲清结论，细节、边界和坑放在后面。复习时只读开头就能判断要不要往下看。

### 可验证

关键结论都要对应仓库里能跑的代码或命令，不写「理论上」。验证命令放在「配套实验」一节，路径指向 `jwt-lab/` 之类的真实目录。

### 同一内容只写一处

概念只在 Wiki 里写一次。课程 README、代码注释只讲「怎么做」，需要解释「为什么」时链接到这里，不复制正文。

## 目录结构

```
docs/
├── index.md              首页：只放通用内容，不出现具体主题名
├── guide.md              本页：全局约定
└── <主题>/
    ├── index.md          主题总览（标题与排序从这里读）
    └── <笔记>.md
```

## 新增一个主题

1. 建目录和总览页：

   ```bash
   mkdir -p docs/network
   ```

   ```md
   ---
   title: 计算机网络
   order: 2
   ---

   # 计算机网络

   这个主题要解决的问题、配套代码在哪。
   ```

2. 写笔记，每篇带上 `title` 和 `order`：

   ```md
   ---
   title: TCP 三次握手
   order: 1
   ---

   # TCP 三次握手

   > 一句话结论。
   ```

3. `./dev` 看一眼侧边栏和搜索，提交。

**不需要改配置**：侧边栏分组、排序、组标题都从目录和 front-matter 生成。

## front-matter 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 侧边栏、搜索结果、浏览器标题里显示的名字 |
| `order` | 否 | 同目录排序，小的在前；`index.md` 永远排第一 |
| `description` | 否 | 页面摘要，用于搜索结果和 SEO |
| `tags` | 否 | 预留给以后的标签页 |
| `updated` | 否 | 人工确认的最后更新日期 |

## 为什么这样组织

- **配置里不出现主题名**：新增主题不用改 `config.mts`；
- **首页里不出现主题名**：首页只做入口，主题入口由侧边栏承担；
- **主题名只出现在自己的 `index.md`**：改名、调序都只改一处。
